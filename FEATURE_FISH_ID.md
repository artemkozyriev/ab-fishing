# Feature: определение вида рыбы по фото

Статус: **реализовано и обучено (вариант 1, TF.js on-device, оффлайн)**. Модель работает.
Создано: 2026-09-27. Обновлено: 2026-09-28.
Идея: пользователь фотографирует пойманную рыбу → приложение определяет вид → сразу
показывает правила/лимиты/сезоны по этому виду (переиспользуя существующий экран detail).

## Архитектура (двухэтапная, всё оффлайн)
1. **MobileNet v2** (вшит в `app/vendor/mobilenet/`, ~14 МБ) → эмбеддинг фото (1280-мерный вектор).
2. **Обученная голова** (`app/model/model.json`, ~95 КБ) → 19 видов Альберты (softmax).

TF.js-рантайм (`app/vendor/tf.min.js`) + оба этапа кэшируются service worker'ом (`ab-fishing-v11`)
→ распознавание работает **полностью оффлайн**. Одинаковый MobileNet + нормализация ([0,1])
на обучении и в браузере → эмбеддинги совпадают.

## Точность (честный holdout, 534 фото, 15%)
- **top-1 ≈ 45%**, **top-3 ≈ 72%** на 19 классах. Потолок ограничен «замороженными» признаками
  MobileNet + шумными фото iNaturalist + похожими видами (форели, сиговые, walleye/sauger).
- Поэтому UX опирается на top-3 и порог уверенности (`CONFIDENT=0.6`): уверенный матч → один
  результат; иначе — «не уверен, ближайшие варианты» + дисклеймер сверять с офиц. определителем.

## Что сделано (код + модель)
- Вкладка **📷 ID** + экран `#screen-id` в `app/index.html` (камера через
  `<input type="file" accept="image/*" capture="environment">`, превью, статус, top-3, бары).
- `app/fishid.js` — инференс: фото → `mobilenet.infer(img,true)` (эмбеддинг) → `head.predict` →
  softmax → top-3. Результат → `window.ABFishing.showSpecies()` (мост в `app/app.js`) → список,
  отфильтрованный по виду → существующий экран правил. Классы 1:1 совпадают с `data/meta.json`.
- Ленивая загрузка: `tf.min.js` + `mobilenet.min.js` подгружаются только при первом распознавании
  (старт приложения не тормозит).
- Модель обучена локально на GTX 1660 (Node-пайплайн, без Python), лежит в `app/model/`.

## Пайплайн (воспроизводимо)
- `npm run fetch-fish` (`scripts/fetch-fish-images.mjs`) — CC-фото с iNaturalist по 19 видам
  → `data/fish-images/<LABEL>/` + `CREDITS.csv`. Собрано ~3 557 фото.
- `npm run train-fish` (`scripts/train-fish-tfjs.mjs`) — `@tensorflow/tfjs-node`: извлечение
  MobileNet-эмбеддингов (кэш в `data/fish-emb-cache.*` → повторы мгновенны) + аугментация
  горизонтальным отражением + линейная голова (dropout 0.5 + L2, early stopping). Пишет
  `app/model/{model.json,weights.bin,labels.json}` и печатает top-1/top-3.
- Альтернатива на Python/Keras (end-to-end MobileNetV2 + `tensorflowjs`): `npm run train-fish-py`
  (`scripts/train_fish_model.py`) — если понадобится fine-tuning базы. Требует Python 3.10/3.11.
- ⚠ tfjs-node на Windows: если биндинг не грузится, скопировать `tensorflow.dll` рядом с
  `tfjs_binding.node` (см. `app/model/README.md`).

## Как улучшить точность (по убыванию отдачи)
- **Fine-tuning MobileNet** (разморозить верх базы) вместо линейного пробинга — Python-пайплайн.
- **Чистка датасета**: iNaturalist отдаёт подводные/рисунки/пейзажи — фильтр «рыба крупным планом».
- Больше фото по трудным/малым классам (walleye 159, tiger trout — гибрид).
- Test-time augmentation, ансамбль кропов; больший base (EfficientNet-Lite).
- ⚠ Оффлайн-бандл вырос на ~15 МБ (MobileNet 14 МБ + TF.js 1.4 МБ) → проверить лимиты iOS Safari.

## Почему хорошо ложится на проект
- Задача — **классификация на ~20 фиксированных видов Альберты** (список уже есть в
  `app/data/meta.json` → `stats.species`), а не «узнать любую рыбу в мире». Это сильно
  упрощает модель и повышает точность.
- Приложение — **offline-first PWA** без сборщика (vanilla JS + service worker). Решение
  желательно мерить этим стандартом.
- Есть куда «приземлить» результат: определили вид → `state.species` → `filterBySpecies`
  / экран detail с правилами. Логика уже написана.

## Три варианта реализации

### Вариант 1 — On-device ML (TensorFlow.js). РЕКОМЕНДУЕМЫЙ
Лучше всего подходит философии офлайна.
- Модель MobileNetV3 / EfficientNet-Lite, дообученная (transfer learning) на ~20 видов,
  конвертированная в TF.js, лежит в `app/` и кэшируется service worker'ом → **работает
  офлайн**, без серверов и ключей.
- Размер модели ~3–15 МБ (офлайн-данных уже ~24 МБ — вписывается).
- Минус: нужен **датасет и обучение** — это главная работа, не код.
  - Источники картинок: iNaturalist, FishBase, GBIF (фильтр по видам Альберты).
  - Дообучение: transfer learning, пара часов на GPU.
- Точность на 20 классах при нормальном датасете рабочая, но фото «рыба в руке» капризны
  (ракурс, вода, блики) → нужен честный порог уверенности и режим «не уверен → топ-3».

### Вариант 2 — Облачный vision-API. Самый быстрый MVP, но ломает офлайн
- Варианты API: Claude/GPT vision (general), Google Vision, профильный **Fishial.ai**
  (специализированный fish-recognition).
- Плюс: интеграция за вечер, высокая точность без своего датасета.
- Минусы: нужен интернет + ключ + стоимость за вызов; ключ нельзя держать в статичном
  GitHub Pages → понадобится тонкий прокси/функция. Противоречит позиционированию «offline».

### Вариант 3 — Гибрид
Онлайн — зовём API (лучшая точность), офлайн — падаем на бандл TF.js.
Максимальная гибкость, но и работы вдвое.

## Точки интеграции в коде (для любого варианта)
- Захват фото — без библиотек:
  `<input type="file" accept="image/*" capture="environment">`.
- Новая вкладка «📷 ID» в `#tabbar` (рядом с List/Map) + новый `<section class="screen">`
  в `app/index.html`.
- Результат классификации → маппинг на существующий `state.species` → переход на экран
  правил. Переиспользуется уже написанная логика фильтра/detail в `app/app.js`.
- Модель/скрипты (TF.js) кэшировать в `app/sw.js`.
  ⚠️ При изменении файлов в `app/` — поднять версию `CACHE` в `sw.js`.

## Рекомендованный план
Целевой вариант — **TF.js on-device** (проект построен вокруг офлайна). Чтобы быстро
проверить продуктовую ценность, разумно начать с облачного MVP, а модель обучить потом.

Возможные первые шаги (выбрать при старте):
- **(A)** Прототип UI (кнопка камеры + экран результата + переход к правилам) на
  заглушке-классификаторе — увидеть UX без ML.
- **(B)** Реальный облачный MVP через vision-API.
- **(C)** Пайплайн обучения TF.js-модели: сбор датасета по 20 видам + скрипт дообучения
  + экспорт в `app/`.

## Открытые вопросы / риски
- Датасет: сколько картинок на вид, лицензии (iNaturalist/GBIF — разные лицензии).
- Точность и UX при низкой уверенности (порог, топ-3, «не удалось определить»).
- Похожие виды между собой (брук/браун/радужная форель; walleye/sauger) — трудные классы.
- Размер модели vs лимиты офлайн-кэша на iOS Safari (см. TODO в STATE.md про iOS).
